# Module 3 Practice v2 — approved direction, 13 September 2026

The owner approved the student-perspective review's recommended revision with
“let's do it”. This authorizes the scoped Module 3 Practice change despite the
earlier sequencing hold; it does not establish Module 2/3 learner acceptance or
authorize Module 4 work. Existing theory pages and final questions are preserved.

## Student journey

Continue the Module 2 Codex task and read its five approved planning documents.
Agree on the first manageable part, then build according to that plan. After
each part Codex explains the result, runs checks and shows the website; the
student supplies observations and accepts or requests changes before continuing.
The four former page sections are examples, not mandatory steps.

One learner-directed improvement and one evidence-based debugging investigation
are required. Either can happen during the build, in either order. An improvement
may refine an existing feature; an extra feature is not required. Earlier real
debugging counts. If no real bug occurs, agree on a reversible practice fault,
record that it is simulated and remove it before final review. Never fabricate
learner observations or approvals.

Codex maintains three supporting records: `evidence/module-3/build-log.md`,
`evidence/module-3/learning-record.md`, and
`evidence/module-3/browser-validation.md`. Their headings are guidance, not an
exact-string grading language. Students own observations, explanations and
decisions; Codex maintains technical identifiers and verification records.

The student inspects the current website, explicitly accepts it and submits one
final package. Deterministic checks inspect actual files, required planning inputs,
the app and a bounded source fingerprint; AI review reads the records and plan
along with the bound task context. It assesses incremental learner acceptance,
PRD coverage, improvement, debugging and current desktop/mobile checks. Approval
does not itself pass the review. A failed or stale review resumes the same task.
The existing five final questions remain independently required.

## Compatibility and integrity

Use Practice version 2.0.0 and retain the v1 definition and artifacts as history.
Preserve tasks, workspace files, archived attempts and old receipts. Migrating an
old active attempt requires the same readable bound task and archives the old
attempt before clearing approval/review in a new generation. No v1 receipt grants
v2 completion. Source or evidence changes invalidate final approval and review.
Module 4 handoff records the v2 reviewed source and evidence, not invented stage
or fixed-slice receipts. Existing v1 data remains readable.
